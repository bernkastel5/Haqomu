# Arabic Lookup — словарь по выделенному слову + карточка в Anki

Android-приложение: выделяешь арабское слово в любом приложении → пункт в меню действий →
попап со значением и примером → кнопка «в Anki».

> **Статус:** в работе. Сейчас в репозитории — инструменты сборки словарных паков.
> Приложение появится отдельно.

---

## Данные словарей в репозитории отсутствуют

И это осознанное решение, а не забывчивость.

| Источник | Что даёт | Почему не в репозитории |
|---|---|---|
| **KSAA / معجم الرياض** (`siwar.ksaa.gov.sa/api`) | современный арабский, огласовка, корень, вес, примеры | запрашивается по сети в момент тапа; перепубликация запрещена условиями |
| **Hans Wehr, 4-е изд. (1979)** | перевод на английский, идиомы, породы | охраняется авторским правом (Harrassowitz / Spoken Language Services) |
| **Wiktionary / Kaikki** | ar→en, широкое покрытие | CC-BY-SA — **можно** распространять с атрибуцией, но пак собирается локально |

Модель как у Yomitan: движок открыт, словари пользователь подключает сам.
Репозиторий содержит **код, который собирает пак из вашего локального файла**, и ничего больше.

```
data/            # игнорируется git: сюда кладётся исходный словарь
packs/           # игнорируется git: сюда собираются паки
tools/           # в репозитории: сборка, инспекция, проверка
```

## Набор Haqomu для Anki

Артефакт `haqomu.apkg` — колода `Haqomu` + note type `Haqomu Arabic` (адаптация JP Mining Note,
фуригана → ташкиль) + одна вводная карточка. Словарных данных не содержит, распространять можно.
Тот же файл вшит в APK как `res/raw/haqomu.apkg` — пользователь ставит колоду и формат
кнопкой «Поделиться набором Haqomu» на экране «Настройка Anki».

```
python3 tools/build_haqomu_apkg.py --out haqomu.apkg
```

Генератор самодостаточен (stdlib); id модели и колоды фиксированы, поэтому повторный импорт
обновляет, а не дублирует. Формат совпадает с эталонным выводом `genanki` (legacy `.anki2`),
структура таблиц и JSON сверена с эталонным выводом `genanki` (совпадают побайтово, кроме времён); молчаливый тест-импорт на AnkiDroid и Anki Desktop — обязательный шаг фазы 10 (выпуск).

## Быстрый старт (сборка пака Hans Wehr)

```bash
# 1. исходник: sqlite из проекта OCR-оцифровки 4-го издания
mkdir -p data/raw
curl -L -o data/raw/hanswehr.sqlite \
  https://raw.githubusercontent.com/GibreelAbdullah/HansWehrDictionary/HEAD/assets/hanswehr.sqlite

# 2. осмотреть исходник (что внутри, где шум)
python3 tools/hw_inspect.py data/raw/hanswehr.sqlite --resolve

# 3. собрать чистый пак
python3 tools/build_hw_pack.py --src data/raw/hanswehr.sqlite --out data/packs/hanswehr

# 4. проверить результат
python3 tools/verify_pack.py data/packs/hanswehr/hw_pack.sqlite
```

Результат: `hw_pack.sqlite` (~8 МБ), `hw_pack.jsonl.gz` (~1.7 МБ) и `build-report.md`
со статистикой и 25 случайными статьями для проверки глазами.

## Что делает сборщик

1. `VACUUM` (16.7 МБ → 11.3 МБ исходника)
2. пересчёт флага «корневая статья» (2–5 арабских букв, без пробела)
3. восстановление иерархии «корень → производные»: в источнике она сдвинута на один
   корневой блок, привязка идёт по ближайшему предшествующему заголовку
   (подтверждается лингвистическим инвариантом на ~84% слов)
4. разбор статьи на поля: `headword`, `romanization`, `body`, `idioms` (после `│`),
   `verb_forms` (породы `I…X`), `plurals` (`pl. …`), `alt_root` (корень в скобках)
5. чистка: номера страниц, надстрочные цифры, кавычки, ведущие `and`/`)`
6. разрешение отсылок `see X` → `see_entry_id`
7. индекс форм: заголовок, вариант без артикля, корень из скобок, множественные числа
8. удаление нерабочей таблицы транслитерации источника (85% расхождений с текстом статей)

## Схема пака

```sql
entries(id, kind, headword, headword_vocalized, headword_norm, romanization,
        body, idioms, verb_forms, plurals, alt_root, root_id,
        quran_occurrence, see_entry_id, flags)
forms(form, entry_id, kind)   -- kind: word | root | plural | xref ...
meta(k, v)
```

`kind`: `root` | `word` | `xref` | `xref_alpha`. `flags` может содержать
`root-unverified`, `no-root`, `xref-unresolved`, `no-romanization`.

## Проверка при импорте в приложение

Единый формат пака (`docs/architecture.md`, §4: `meta` / `entry` / `sense` / FTS5 `sense_fts`)
приложение проверяет **до установки**: обязательные таблицы и колонки, `meta`
(`schema_version=1`, `source`, `license`, `build_date`, `entry_count`, языковая пара),
соответствие `entry_count` числу строк, отсутствие смыслов-сирот и рабочий модуль FTS5.
Файл, не прошедший проверку, не устанавливается. Пак Hans Wehr собирается скриптом
`tools/build_hw_pack.py` и имеет собственную схему (см. выше); конвертер в единый формат —
отдельный шаг фазы 4.

## Известные ограничения

- **Омографы.** ~3 400 слов имеют 2+ статьи (`صفر` — 8). Лукап возвращает несколько
  кандидатов; выбор — задача ранкера на клиенте, пак даёт данные для этого.
- **Словоформы.** `قال`, `عين`, `صلاة` не имеют отдельного заголовка: Wehr держит их
  внутри корневых статей. Нужен деинфлектор (в `tools/verify_pack.py` есть его прототип:
  отсечение клитик + правило `-ات` → `ة`; на контрольном наборе 15/15).
- **Породы** размечены только в 8% статей — в остальных OCR потерял жирный шрифт.
- **Кораническая конкорданция** из источника не включена: там `ROOT_WORD` — не корни
  (в топе `و`, `ال`, `ل`), и нет текста аятов.

## Как измеряется качество

Качество словаря измеряется не на глаз, а на «золотом наборе»: 200 самых частотных
арабских слов (OpenSubtitles 2018, 4 полосы по 50), размеченных вручную, и три
стратегии — KSAA как отдаёт API, KSAA с ранкером, Hans Wehr через пак.

```
python3 tools/collect_golden.py     # выборка слов + запросы к KSAA (~40 c, кэш в data/quality/ksaa_cache)
python3 tools/build_kaikki_index.py # индекс Kaikki/Wiktionary ar→en (дамп 72 МБ gz -> 6 МБ индекса, ~40 c)
python3 tools/score_kaikki.py       # прогон по Kaikki с клиентским ранкером
python3 tools/pipeline_kaikki_ksaa.py  # лемма от Kaikki -> значение от KSAA (пайплайн)
python3 tools/crossrank.py          # кросс-словарное подтверждение
python3 tools/pipeline_full.py      # полный пайплайн: анализатор -> фильтр -> голосование
python3 tools/sense_prior.py        # приор порядка смыслов (проверен, отклонён: +3 слова)
python3 tools/score_golden.py       # разметка + метрики -> data/packs/hanswehr/quality-report.md
```

Результаты на текущий момент (доля верных первых значений на 188 настоящих словах):
KSAA без ранкера — 54%, с ранкером — 57%, Hans Wehr — 52%, Kaikki ar→en — 53%.
Объединение двух ar-словарей — 74%, всех трёх — 86% (88% с частично верными).
Пайплайн «лемма Kaikki → значение KSAA» на всех словах даёт 40% (хуже прямого запроса),
зато как страховка при пустом ответе добавляет 4 слова без потерь — 60% на 188.

Итоговая архитектура — **анализатор → фильтр → кросс-подтверждение**: 71% верных первых
значений на 188 словах (против 57% у лучшего одиночного словаря), пустых ответов 8 вместо 30.
Анализатор — `farahidi` (порт AlKhalil Morpho Sys 2, GPL-3, офлайн): см. `docs/morphology-analyzers.md`.
Перед запуском пайплайна нужен `pip install farahidi` — пакет не входит в репозиторий.
Приор порядка смыслов проверен и отклонён (+3 слова ценой 51 переписанного ответа).
Выбор смысла мелкой моделью на устройстве проверен: 0.6B (379 МБ) не различает смыслы
(парный тест с балансировкой порядка — 0/10, ответ «первый вариант» в 100% случаев).
Скрипты: `tools/eval_sense_llm.py`, `tools/eval_sense_pair.py`, нужен GGUF в `models/` (не в git).
Выбор смысла специализированной моделью: **ArabGlossBERT** (`SinaLab/ArabGlossBERT`, CC-BY-SA-4.0,
135 млн параметров, int8 ~135 МБ) — 76% на парах против 50% случайности, ожидаемый выигрыш
на живых данных ~+5 п.п. На живых предложениях (Tatoeba + арабская Википедия, ручная разметка, n=101): 68% против 50%
у словарного порядка без порога, **76.6% против 70% с порогом разрыва вероятностей 0.3** —
то есть +6–7 п.п. при вмешательстве в 18% запросов. Формат fp16 270 МБ или int8 ~135 МБ:
квантование в int8 точность не меняет (69/101 в обоих случаях).
Скрипты: `tools/eval_arabglossbert.py`, `tools/eval_agb_multi.py`, `tools/eval_live.py`
(нужен `transformers` + веса в `models/agb/`, в git не попадают).
Порог уверенности и int8: `tools/eval_int8.py`; разметка 101 элемента — `data/quality/live_labels.json`.

Метрика MVP — «нужное значение есть в попапе»: сейчас **84%** (168/200), после исправления
леммы и показа второй статьи — **87%**; без имён собственных в знаменателе 89% → **92.5%**.
Половина промахов — транслитерированные имена (12) и служебные связки (8), а не смыслы.
Пайплайн v2 (`tools/pipeline_v2.py`: класс имени + леммы CAMeL + попап на 3 статьи):
**186/200 = 93.0%** (диапазон 92.0–93.0% с учётом спорных меток). Класс имени проверяет
основу по словарю и совместимость аффикса (`tools/name_class.py`); ложных «имён» нет.
Разделение по уверенности: ответ, подтверждённый двумя словарями, верен в 73% случаев,
неподтверждённый — в 28%.
Потолок KSAA при идеальном ранкере — 70%: у половины провалов верной статьи нет
в ответе API вообще. Отчёт с таксономией провалов — `quality-report.md`.

Разметка лежит в `data/quality/golden200-labels.csv` и, как все данные, не публикуется.

## Тестовая сборка для телефона

CI собирает debug-APK (`:app:assembleDebug`), а скрипт `tools/publish_apk.sh` после сборки
кладёт его в ветку **`apk-build`** — одной ревизией без истории — и, если прогону доступен
токен, в релиз **`apk-latest`**. APK в основной ветке и в истории не появляется.

- Ветка: `apk-build/haqomu-debug.apk` (+ `BUILD.txt` с коммитом и размером)
- Релиз: <https://github.com/bernkastel5/Haqomu/releases/tag/apk-latest>

Публикация требует **права записи у токена рабочего процесса**:
Settings → Actions → General → Workflow permissions → *Read and write permissions*.
Пока стоит read-only, сборка зелёная, а шаг публикации выдаёт предупреждение
в аннотациях прогона.

Установка: скачать файл на телефоне, разрешить установку из этого источника, открыть.
Пакет `com.bernkastel5.haqomu.debug` — ставится рядом с release-версией; подпись —
отладочный ключ CI (для магазина нужна отдельная, фаза 10). Словарные паки и модель
смыслов в APK не входят: их ставит пользователь на экранах «Импорт паков» и «Модель смыслов».

## Модель разрешения смыслов (необязательно)

Модель подсказывает, какой смысл статьи подходит к предложению. Весов в репозитории и в APK нет
(CC BY-SA 4.0): бандл (`model.onnx` + `vocab.txt` + `model.json`) собирается у вас и устанавливается
на экране «Модель смыслов» файлом или по адресу. Порог уверенности — 0.3, порядок статей не меняется.

```bash
# из готового экспорта
python3 tools/make_model_bundle.py --onnx agb_int8.onnx --vocab vocab.txt \
    --name "ArabGlossBERT int8" --out haqomu-agb-int8.zip

# либо скачать SinaLab/ArabGlossBERT и экспортировать (optimum + transformers + onnxruntime)
python3 tools/make_model_bundle.py --from-hf --quantize int8 --out haqomu-agb-int8.zip
```

## Сборка приложения (для разработчиков)

Каркас: Kotlin + Jetpack Compose, один модуль `app`. Словарные данные в репозиторий и в APK не входят (см. выше).

Требования: JDK 17, Android SDK (compileSdk 35), Gradle 8.9 (или `gradle wrapper --gradle-version 8.9`).

```bash
gradle :app:assembleDebug :app:testDebugUnitTest
```

Сервис доступности (плавающая кнопка, Ф2/Ф3) выключен по умолчанию, включается только в системных
настройках доступности; отдельного разрешения «поверх других приложений» не требует (окно
`TYPE_ACCESSIBILITY_OVERLAY`). Текст экрана читается только в момент выделения и не сохраняется —
подробности в `docs/adr/0007-accessibility-service.md`.

CI: `.github/workflows/build.yml` — сборка, юнит-тесты, проверка Python-инструментов. Версии зависимостей зафиксированы в `gradle/libs.versions.toml`; обновление — отдельным изменением. Состояние проекта и план — `PROJECT_STATE.md`; решения по стеку — `docs/adr/`.
