# ADR 0008: модель разрешения смыслов (ArabGlossBERT, ONNX Runtime)

Статус: принято 2026-11-14

## Контекст

Ф10 (опциональная модель, `should`) и Ф13 (загрузка/удаление, `should`). TZ §6.3–6.4 задаёт
жёсткие правила: смысл меняется **только** при разрыве вероятностей ≥ 0.3, статья остаётся
на своём месте, ответ базового пайплайна — по-прежнему первая статья (регрессия недопустима).
Измерения (architecture §2.7): без порога модель портит 32% верных ответов, с порогом
молчит в 82% запросов и даёт ~76.6% против ~70% у словарного порядка на 101 живом
предложении. int8 точность не меняет (69/101 в обоих случаях).

Ограничение среды: Maven Central и Google Maven из песочницы недоступны, поэтому
зависимость проверяется только CI (R12); весов модели в песочнице нет — приёмка по
`live_labels.json` остаётся на машине заказчика.

## Решение

1. **Рантайм — ONNX Runtime for Android** (`com.microsoft.onnxruntime:onnxruntime-android`,
   версия 1.20.0, MIT, официальный Maven Central-артефакт). Альтернативы отклонены:
   Chaquopy/PyTorch Mobile — десятки мегабайт лишнего рантайма, TFLite — нужен свой экспорт
   и нет готового артефакта с той же точностью. ORT тянет нативные `.so` на несколько ABI:
   в APK добавляется ~30 МБ, весов там нет.
2. **Веса не вшиваются и не раздаются** (TZ §5.1, D-014; CC BY-SA 4.0). Пользователь получает
   бандл сам: «Модель смыслов» → «Скачать» с указанного им адреса или «Выбрать файл…».
   Адрес по умолчанию **не задан**: Hugging Face из песочницы недоступен, а «кнопка в никуда»
   хуже честного поля. Скрипт `tools/make_model_bundle.py` собирает бандл у пользователя
   (из готового `model.onnx` или прямо с HF через `optimum`, с int8/fp16).
3. **Формат бандла — наш**: zip из `model.onnx`, `vocab.txt`, `model.json`. Манифест
   содержит только то, что приложение читает: имя, версию, лицензию, источник, размер,
   `max_length`, флаги токенизатора, имена входов/выхода, число классов, порог.
   Проверка до установки (`ModelBundle`): три файла, потолок распаковки 400 МБ, манифест
   разбирается, `labels == 2`, `max_length` 16..512, служебные токены в словаре.
   Установка атомарная: распаковка в `filesDir/model.tmp` → проверка → подмена `filesDir/model/`.
4. **Токенизатор свой** (`BertTokenizer`): WordPiece-правила BERT (clean_text → strip_accents
   → базовая разбивка → жадный префикс → `##`), пара кодируется `[CLS] A [SEP] B [SEP]`
   с `token_type_ids`. Снимать `strip_accents` для арабского = снимать харакат (они
   nonspacing-метки), что совпадает с нормализацией замера (`HAR` в `tools/eval_live.py`).
   Библиотека токенизаторов не нужна: одна модель, один словарь, правила проверяемы тестами.
5. **Порог и порядок — в чистой логике** (`SenseRanking`, `SenseResolver`), ONNX — только
   в `OnnxSenseModel`. Правила: смыслов ≥ 2; лучший не первый; разрыв ≥ 0.3 (с допуском 1e-9,
   иначе 0.7 − 0.4 в double даёт 0.29999999999999993); перестановка только внутри первой
   статьи, все смыслы остаются; любая ошибка модели → словарный порядок, попап не падает.
   Оцениваются до 6 смыслов; модель запускается только при непустом предложении (TZ §3.2).
6. **Пометка в интерфейсе**: если смысл поднят моделью, у статьи появляется подпись
   «Смысл выбран моделью» — пользователь видит, что порядок не словарный.
7. **Кэш сессии** (`SenseModelCache`): одна сессия ORT на процесс, сбрасывается при
   установке/удалении/выключении модели; загрузка графа не повторяется на каждый попап.

## Что осознанно не сделано

- **Батч из нескольких смыслов** за один прогон ORT: экономит миллисекунды на 1–6 смыслах,
  но усложняет сборку `attention_mask`; p95 с моделью < 700 мс (TZ §6.5) достигается и так.
- **Автозагрузка с Hugging Face без адреса**: без подтверждённого URL кнопка врала бы.
  Поле адреса + выбор файла + скрипт сборки бандла закрывают оба сценария (D-018: телефон
  без ПК тоже работает — файл можно скачать в браузере).
- **Точные метрики на `live_labels.json`**: фикстура с текстом статей в песочнице
  не публикуется и не передавалась; прогон `tools/eval_live.py` — на машине заказчика
  (вопрос 15 §8 PROJECT_STATE).

## Последствия

- APK растёт на размер нативного рантайма ORT (~30 МБ на все ABI); весов в APK нет.
- `gradle/libs.versions.toml`: `onnxruntime = "1.20.0"`; обновление — отдельным изменением.
- Строки RU/EN/AR: 236 ключей в каждой локали; новые — экран «Модель смыслов» полностью.
- JVM-тесты: `BertTokenizerTest`, `SenseRankingTest`, `ModelBundleTest`, `SenseResolverTest`
  (без ONNX и Android); проверка самого ORT — CI-сборка + прогон на устройстве.
