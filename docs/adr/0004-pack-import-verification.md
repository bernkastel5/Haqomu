# ADR-0004: Импорт паков — копирование, полная проверка, приватное хранилище

Дата: 2026-11-14 · Статус: принято · Ветка: `arena/609280e4-haqomu`

## Контекст

Приложение не содержит словарных данных (APK пуст). Паки собирает сам пользователь
(D-007, TZ §5). Экран импорта обязан решить три задачи: не принять битый файл,
не перепутать формат, ничего не увидеть, кроме своего приложения. Фаза 4 трека ТЗ
(Ф12) и architecture §4.

## Решение

1. **Поток импорта:** пикер (`OpenDocument`, удержание read-permission) → копия в
   `cacheDir` → проверка → при успехе установка (rename) в `filesDir/packs/`,
   при неудаче временный файл удаляется. Исходный файл пользователя не изменяется.
2. **Чек-лист проверок (порог «не импортировать», architecture §4 + verify_pack.py):**
   читаемость файла; обязательные таблицы `meta/entry/sense/sense_fts`; обязательные
   колонки; `meta` ключи `schema_version(=1), source, license, build_date, entry_count`;
   языковая пара (принимаются `lang_from/lang_to` из architecture §4 и `language_from/language_to`
   из TZ §5.2 — документы расходятся, поэтому принимаем оба); `entry_count` из meta ==
   `COUNT(entry)`; пакет непуст; нет смыслов-сирот (`sense.entry_id` без `entry.id`);
   `head_norm` заполнен; FTS5 модуль работает (запрос к `sense_fts` валиден).
3. **Реализация:** чистая логика `pack/PackChecks.kt` (интерфейс `PackDataSource`,
   юнит-тесты на синтетике в `test/`), Android-специфика изолирована в
   `pack/AndroidSQLitePackSource.kt` (read-only нативный SQLite).
4. **Хранение:** `filesDir/packs/*.sqlite`, приватно для приложения; удаление — кнопка
   «Удалить» на экране импорта. Никакого доступа других приложений, никакого экспорта.
5. **Что НЕ делаем на этом шаге:** проверка схемы Hans Wehr (другой формат, verify_pack.py
   сильно специфичнее), сборка KSAA на устройстве (D-007/D-019, нужен отдельный ADR после
   получения дампа), встроенный конвертер camel-msa-r13 → SQLite на устройстве
   (ADR-0003, отдельныый порт build_camel_pack.py), импорт KSAA из Termux.

## Последствия

- Экран импорта даёт честный отчёт по каждому чеку (галка/крест + деталь) до установки.
- Юнит-тесты покрывают ветвления проверки без Android SDK; FTS5-проверка подтверждается
  только на устройстве/CI с Android SQLite (на JVM она проверяется фейком).
- Невалидный или чужой `.sqlite` отклоняется до того, как попадает в папку приложения.
