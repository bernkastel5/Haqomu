# ADR 0011: смысл по предложению без модели, огласовка по морфологии, встроенная читалка

Статус: принято 2026-11-14

## Контекст

Три запроса заказчика, все — про «одно и то же слово, но в книге»:

1. Приложение **не считывает предложение** с выделенным словом, хотя должно: на его
   основе должен подниматься нужный смысл, когда смыслов у слова несколько.
2. В карточке поле «слово» приведено к нормальной форме, но **без огласовки**; нужно
   расставлять огласовку, когда её нет, «если решение не слишком тяжёлое».
3. Нужна **встроенная читалка**: книги любых форматов, прежде всего EPUB (как ttsu
   reader внутри Jidoujisho) и PDF **с выделяемым текстом**; выделение должно идти в тот
   же попап и карточку. Сканы без текстового слоя — отдельная задача, не сейчас.

Что уже было в проекте: сервис доступности вырезал слово и предложение
(`SelectionCapture` → `SentenceExtractor`), но дальше `SelectionHub` → интент попапа —
и там контекст использовала **только модель** (`SenseResolver`), а модель по умолчанию
выключена и весов в APK нет. Итог: пользователь видел строку контекста в попапе, но
порядок смыслов не менялся — «контекст есть, смысла нет».

База морфологии calima (`camel_pack.sqlite`) уже лежит на устройстве; в ней есть
огласованный разбор каждой словоформы (`diac`), но конвертер его выбрасывал, оставляя
только стебель без огласовки.

Ограничения среды: Maven Central/Google Maven из песочницы недоступны, поэтому любая
новая зависимость проверяется только CI и увеличивает APK без гарантии, что она нужна.
Отсюда курс на решения на своём коде там, где это честно возможно.

## Решение

### 1. Контекст работает всегда: модель, затем эвристика по предложению

`SenseResolver` теперь применяет два механизма по порядку:

- **модель** (как раньше, если установлена и включена): порог 0.3, разрыв вероятностей,
  поднимается один смысл внутри первой статьи;
- **`ContextRanking`** — детерминированная эвристика по предложению: слова предложения
  ищутся в тексте толкования (+1 за совпадение, стоп-слова исключены), часть речи
  разбора совпадающая с пометкой толкования («اسم»/«فعل»/«صفة») даёт ещё +1.
  Смысл поднимается только при собственном балле ≥ 2 и перевесе ≥ 1 над текущим первым.

Порог модели (0.3) **не переиспользуется**: это калиброванное правило измеренной модели,
а у эвристики целые баллы. Помечаются они по-разному: «Смысл выбран моделью» и «Смысл по
предложению», чтобы интерфейс не приписывал эвристике уверенность модели. Инварианты
TZ §6.3 сохраняются: статья остаётся первой, смыслы не удаляются, без предложения —
словарный порядок.

Отдельно починен **ввод контекста**: `SelectionLocator` восстанавливает выделение, когда
система его не додала (WebView/Compose/браузеры отдают выделенный текст в событии без
смещений, а иногда и без текста узла). Раньше сервис в этих случаях молча выходил, и
контекста не было вовсе — самая частая причина «не считывает предложение».

### 2. Огласовка — из морфологической базы, а не из модели

Нейросетевой Tashkeel (CATT, Mishkal и аналоги) — это ещё одна модель на десятки-сотни
мегабайт и ещё один путь «скачай и поставь». Он отклонён: база calima уже даёт
огласованный разбор словоформы, и огласовка превращается в поиск, а не в предсказание.

- в пак добавлена колонка `stems.stem_diac` (огласованный стебель из `diac`);
  старые паки читаются как раньше — колонки нет, огласовки нет;
- `StoreTashkeelSource` перебирает те же сегменты, что анализатор, и собирает
  «префикс + стебель + суффикс» с огласовкой (у calima огласовка аффиксов приходит
  в feats `diac`, ключи аффиксов хранятся без огласовки);
- `Tashkeel.tashkeel` выбирает самый частотный вариант (`lex_logprob`), вычищает татвиль
  и **проверяет обратимость**: снятая огласовка обязана совпасть с исходной формой,
  иначе возвращается null. Выдуманных огласовок не бывает;
- слово уже с огласовкой — не трогаем; формы нет в базе — поле Tashkeel остаётся
  головой статьи, как раньше (честная деградация).

### 3. Читалка на своём коде, без новых зависимостей

- **EPUB**: `java.util.zip.ZipFile` + ручной разбор `container.xml` → OPF → spine →
  XHTML; `HtmlText` переводит разметку в текст (блочные теги — абзацы, сущности
  раскрываются, `script/style` выбрасываются, арабский текст **не нормализуется**).
  Заголовки глав — из `nav.xhtml` (EPUB 3) или `toc.ncx` (EPUB 2), иначе из первого `h1`.
- **PDF с текстовым слоем**: свой разбор объектов, `Inflater` для `FlateDecode`,
  объекты из `/ObjStm`, порядок страниц по `/Pages` → `/Kids`, операторы `Tj/TJ/'/"`,
  перевод кодов через `/ToUnicode` CMap (`bfchar`/`bfrange`, UTF-16BE). Шрифт
  Identity-H **без** CMap пропускается: латиница на его месте была бы мусором.
- **FB2, HTML, TXT** — там же, одним диспетчером `BookText` (по расширению и по первым
  байтам). Один длинный текст режется на части только по границам абзацев.
- **Тап по слову** (`ReaderSelection`) даёт слово и предложение через те же
  `LookupQuery`/`SentenceExtractor`, что и сервис доступности, и открывает
  `LookupPopupActivity` — то есть тот же попап и та же карточка. Сервис доступности
  для чтения не нужен и не должен быть включён.
- Книга приходит и из других приложений: `OpenDocument` внутри читалки и
  `ACTION_VIEW`/`ACTION_SEND` через `ReaderActivity` (манифест).

Отклонено: PDFBox-Android (заброшен, весит больше приложения), `PdfRenderer`
(умеет рисовать, не умеет отдавать текст), WebView для EPUB (нет доступа к тексту для
выделения без собственного моста, тяжелее и хуже управляется с Compose).

## Что осознанно не сделано

- **OCR сканов** — заказчик вынес отдельно; PDF без текстового слоя честно не открывается.
- **Рендер PDF страницами** — нужен движок рендера; для чтения текста и выделения он не
  требуется.
- **DRM/шифрование PDF и EPUB** — книги с защитой не открываются, и это сказано в тексте
  ошибки, а не показывается пустым экраном.
- **Колонки и таблицы PDF** — порядок текста как в контент-потоке, а не как в вёрстке.
- **Продолжение чтения по закладке** — глава выбирается листанием; хранение позиции
  (и «недавние книги») — следующий шаг, чтобы не добавлять настройку «на будущее».
- **Огласовка глагольных форм по шаблону** — если calima формы не знает, огласовки нет:
  порождать её правилами без проверки значило бы выдумывать.

## Последствия

- Контекст работает без модели: попап отвечает по предложению «из коробки», модель
  остаётся необязательным улучшением.
- Пак морфологии нужно пересобрать, чтобы появилась огласовка (`tools/build_camel_pack.py`
  и конвертер на устройстве пишут `stem_diac`); старые паки продолжают работать.
- Читалка не добавляет зависимостей: APK растёт только на код. Поддержка форматов
  ограничена перечисленными; новый формат — отдельное решение и отдельные тесты.
- JVM-тесты: `ContextRankingTest`, `SelectionLocatorTest`, `TashkeelTest`, `HtmlTextTest`,
  `EpubBookTest`, `PdfTextTest`, `ReaderSelectionTest`, `BookTextTest` (без Android).
