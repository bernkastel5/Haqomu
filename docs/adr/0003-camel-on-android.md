# ADR 0003: морфология CAMeL на Android (спайк фазы 2)

Статус: исследование завершено 2026-11-14; план, не финальная реализация.

## Ключевая находка

`calima-msa-r13` (`morphology.db`, ~40.5 МБ) — это НЕ SQLite, а **текстовый дамп**
со секциями `###DEFINES### / ###DEFAULTS### / ###ORDER### / ###TOKENIZATIONS### /
###STEMBACKOFF### / ###PREFIXES### / ###SUFFIXES### / ###STEMS### / ###TABLE AB### /
###TABLE BC### / ###TABLE AC###`. CAMeL разбирает его в память при старте.

Стебли хранятся **без огласовки** (именно поэтому анализатор работает по
неогласованному входу), `lex` содержит суффикс `_id`, отрезаемый `strip_lex`
(`re.split(r'[_-]', lex)[0]`), `lex_logprob` — качество леммы. Нормализация
анализатора (DEFAULT_NORMALIZE_MAP) совпадает с нашей `un()/key()`:
`إ أ آ ٱ → ا`, `ى → ي`, `ة → ه`, удаление татвиля и огласовки.

## Что нужно приложению

Только анализ верхнего уровня: для слова — список разборов, отсортированных по
`lex_logprob`, из которых берём `pos` и `lex` (лемму). Не нужны: генерация,
reinflection, STEMBACKOFF, TOKENIZATIONS, DEFINES/DEFAULTS, CAPHI, глоссы, паттерны.
Это примерно 10–15% объёма разбора CAMeL.

## Решение (план)

1. Пользователь скачивает calima сам (GPL-2, релиз CAMeL-Lab): `camel_data -i morphology-db-msa-r13`
   или zip из официального GitHub-релиза 2022.03.21. Ничего не зеркалируем и не вкладываем в APK.
2. Конвертация в компактный **SQLite** (`camel_pack.sqlite`): таблицы `stems(stem, cat, pos,
   lex, lex_logprob, root)`, `affixes(form, kind, cat, feats-json)`, `compat(kind, a, b)`,
   `meta(...)`. Чтение — нативный `android.database.sqlite`, индексы по `stem` / `(form, kind)`.
   Собственный бинарный формат отвергнут: SQLite даёт готовые индексы, page cache и не
   требует собственного декодера и его тестирования.
   - Эталон конвертации на Python: `tools/build_camel_pack.py` (selftest на синтетике — OK;
     замеры на реальной базе — на машине с доступом к calima, см. задания в состоянии).
   - Тот же проход нужен **внутри приложения** для пользователей без ПК (D-018): одна кнопка
     «Подготовить морфологию», скачивание ~40 МБ с официального релиза CAMeL-Lab по явному
     согласию, разбор на устройстве с прогрессом (D-019, на утверждение у заказчика).
3. Анализатор в Kotlin — прямое портирование подмножества CAMeL:
   `_segments_gen(word, max_prefix, max_suffix)` → поиск префиксов/стеблей/суффиксов →
   фильтр по таблицам compat → слияние feats по правилу `merge_features` (stem < suffix < prefix,
   перезапись не-('-','') значений) → сортировка по `lex_logprob`.
   Верификация против эталонного Python (`tools/name_class.py`, `pipeline_full.py`) на
   локальной фикстуре (pf_v2.json), цель: попадание леммы в топ-2 на уровне эталона (13/14).
4. Проверка сборки/тестов Kotlin — только CI (локальная песочница без JDK/SDK и без
   Google Maven). CI пока заблокирован: GitHub App без Workflows permission, см. docs/ci/README.md.

## Риски и открытые места

- Размер `camel_pack.sqlite` и скорость разбора на слабом телефоне — замерить на реальной базе
  (цель: файл ≤ 20 МБ, разбор слова p95 < 5 мс; попап влезает в бюджет Ф6.5).
- Насколько точно merge_features влияет на ранжирование лемм на фикстуре — проверяется замером.
- Импорт calima в in-app режиме: 40 МБ по сети + ~10–60 с конвертации — нужен прогресс и
  понятные ошибки (паттерн как с моделью ArabGlossBERT, D-014).
- Лицензии: calima GPL-2 + приложение GPL-3.0 — совместимо; атрибуция CAMeL Tools на
  экране «О программе» обязательна.
