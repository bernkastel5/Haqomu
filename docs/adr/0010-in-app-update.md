# ADR 0010: обновление приложения из релиза, без магазина

Статус: принято 2026-11-14

## Контекст

Тестовые сборки раздаются APK-файлом (GitHub Releases `apk-latest`); магазина нет,
и до сих пор обновление означало «найди ссылку, скачай, поставь поверх». Требование —
сделать обновление удобным и заранее подготовить APK к тому, что версии будут меняться.

Что уже есть в проекте: FileProvider (`file_paths.xml` → `cache-path`), разрешение
`INTERNET`, публикация сборки скриптом `tools/publish_apk.sh`.

## Решение

1. **Канал — тот же релиз.** `UpdateChecker` читает `BUILD.txt` из релиза `apk-latest`
   (постоянный адрес), сравнивает `version_code` со своим `versionCode` и, если релиз
   новее, предлагает скачать `haqomu-debug.apk` оттуда же. Отдельного сервера и
   аккаунтов нет; запросов, кроме двух GET к GitHub, приложение не делает.
2. **VersionCode растёт автоматически.** В `app/build.gradle.kts`:
   `-PhaqomuVersionCode` (в CI — номер прогона) либо время в минутах для локальных
   сборок. Это гарантирует, что собранный позже APK всегда «новее» — иначе системный
   установщик отказал бы в обновлении. `versionName` — `0.2.0` (переопределяется
   `-PhaqomuVersionName`).
3. **Разбор `BUILD.txt` — чистая логика** (`update/BuildTxt.kt`, JVM-тесты):
   формат наш, но старые сборки писали файл без версии — такой файл тоже разбирается
   (обновление не предлагается, коммит показывается).
4. **Установка — системный установщик.** `UpdateChecker.install` отдаёт APK через
   FileProvider; на Android 8+ при отсутствии разрешения открывает
   «Установка неизвестных приложений» именно для нашего пакета, а не просит его глобально.
   Число неудачных попыток запоминается: после повтора экран подсказывает, что включить.
5. **Данные переживают обновление.** Паки (`filesDir/packs`), морфология
   (`camel_pack.sqlite`), настройки (SharedPreferences), очередь Anki и бандл модели лежат
   вне APK. Установка «поверх» меняет только код; схема паков версионируется отдельно
   (`meta.schema_version`), так что старые паки продолжают читаться.
6. **Проверка не чаще раза в сутки**, если пользователь не нажал «Проверить» — чтобы
   не дёргать сеть при каждом запуске.

## Что осознанно не сделано

- **Фоновая автопроверка при старте**: лишний сетевой запрос без действия пользователя;
  проверка доступна с главного экрана («Обновление») в одно касание.
- **Своя подпись и release-канал**: подпись — фаза 10 (ключ вне git, ADR-0002).
  Пока ставится debug-сборка; при переходе на release-подпись установка «поверх»
  debug-версии потребует удаления (системное ограничение Android, не наше).
- **Дельта-обновления**: APK 80 МБ (нативный ONNX Runtime), но раздача идёт через GitHub;
  уменьшение размера — отдельная задача (ABI splits), не часть обновления.

## Последствия

- Обновление: «Обновление» → «Проверить» → «Скачать и установить» → подтверждение в
  системном установщике. Пользовательские данные остаются.
- Номер сборки виден на экране («установлено N»), в `BUILD.txt` и в `AboutScreen`.
- Тесты: `BuildTxtTest` (8 кейсов) — формат, размеры, сравнение версий.
