# ТЗ: арабский словарь-лупа для Android

Версия 1.0 · составлено по итогам измерений на наборе из 200 слов

---

## 1. Что делаем

Приложение для Android, которое показывает словарное значение арабского слова, выделенного
в **любом** другом приложении, и позволяет одной кнопкой добавить карточку в Anki.

Аналог Yomitan, но под арабский и под Android. Работает полностью офлайн, без сервера.

## 2. Границы

**Входит:**
- Android (minSdk 26, targetSdk — актуальный на момент сборки), Kotlin.
- Выделение текста → меню «Обработать текст» (`ACTION_PROCESS_TEXT`) и плавающая кнопка
  через `AccessibilityService`.
- Попап поверх чужого приложения с 1–3 словарными статьями.
- Офлайн-словари из локальных паков.
- Добавление карточки в AnkiDroid.
- Опциональная загрузка модели разрешения смыслов (по желанию пользователя).

**Не входит:**
- iOS, десктоп, веб.
- Собственный бэкенд, аккаунты, синхронизация, аналитика, реклама.
- Онлайн-запросы к словарям в момент работы (всё локально).
- Ввод арабского текста с клавиатуры как основной сценарий (только как отладка).

## 3. Пользовательские сценарии

### 3.1 Базовый: выделил слово → увидел значение

1. В любом приложении пользователь выделяет арабское слово.
2. В контекстном меню выбирает «Словарь» (пункт из `ACTION_PROCESS_TEXT`).
3. Открывается компактный попап: до трёх словарных статей, первая — из арабско-арабского
   словаря, ниже — английские эквиваленты.
4. Пользователь читает, закрывает попап тапом мимо.

### 3.2 С контекстом: модель выбирает смысл

Если доступен текст экрана (`AccessibilityService`), в попапе первой идёт статья,
смысл которой модель сочла подходящим к этому предложению. Модель вмешивается **только**
когда уверена (см. §6.4); иначе попап выглядит как в 3.1.

Если текста экрана нет — попап выглядит так же (те же три статьи, те же 93%), меняется
только порядок смыслов **внутри** статьи: они идут в словарном порядке. Модель в этом
режиме не запускается вообще, потерь в метрике «значение в попапе» нет.

### 3.3 Карточка в Anki

1. В попапе у каждого смысла есть кнопка «В Anki».
2. Открывается экран создания карточки с предзаполненными полями: слово (как выделено),
   лемма, статья, выбранный смысл, предложение-контекст (если был), название словаря.
3. Пользователь правит и сохраняет → заметка уходит в AnkiDroid.

### 3.4 Имена собственные и незнакомые формы

Если слово не является словарным (транслитерация имени, слипшаяся форма с местоимением),
попап показывает честную плашку: «Похоже на имя собственное, словарной статьи нет» +
транслитерацию латиницей, если удаётся построить. Никакого значения случайного арабского
слова вместо этого — это измеренно худший вариант.

## 4. Функциональные требования

| № | Требование | Приоритет |
|---|---|---|
| Ф1 | Пункт «Словарь» в меню выделения текста (`ACTION_PROCESS_TEXT`), приём арабского текста | must |
| Ф2 | Плавающая кнопка через `AccessibilityService` (включается в настройках, выключена по умолчанию) | must |
| Ф3 | Чтение предложения вокруг выделения через `AccessibilityService` | should |
| Ф4 | Нормализация: снятие хараката и татвиля, унификация ا/أ/إ/آ, ى/ي, ة/ه | must |
| Ф5 | Классификатор «словарное слово / форма с клитикой / имя собственное» | must |
| Ф6 | Лемматизация: до двух лемм на словоформу | must |
| Ф7 | Поиск по четырём источникам: арабо-арабский словарь (KSAA-пак), Hans Wehr, Kaikki, коранический конкорданс | must |
| Ф8 | Выбор ответа внутри словаря и голосование между словарями | must |
| Ф9 | Попап с 1–3 статьями, все смыслы статьи видны, порядок как в §6.3 | must |
| Ф10 | Опциональная модель разрешения смыслов с порогом уверенности | should |
| Ф11 | Создание заметки в AnkiDroid из попапа | must |
| Ф12 | Экран импорта/обновления паков (файл → проверка → установка) | must |
| Ф13 | Экран загрузки опциональной модели (270 МБ / 135 МБ) с прогрессом и удалением | should |
| Ф14 | История последних запросов (локально, отключаемая) | could |
| Ф15 | Тёмная тема, размер шрифта, арабская гарнитура с полной огласовкой | should |

## 5. Данные

### 5.1 Паки (все — локальные, в репозиторий не попадают)

| пак | источник | кто готовит | размер |
|---|---|---|---|
| арабо-арабский (KSAA) | дамп KSAA, права на перепубликацию закрыты | **пользователь**, скриптом | ~50–200 МБ |
| Hans Wehr | `hanswehr.sqlite` (16.74 МБ), охраняется авторским правом | **пользователь**, `tools/build_hw_pack.py` | ~20 МБ |
| Kaikki (ar→en) | дамп Wiktionary, CC BY-SA 4.0 | **пользователь**, `tools/build_kaikki_index.py` | 6.1 МБ gz |
| коранический конкорданс | открытый корпус | пользователь | ~5 МБ |
| морфологическая база CAMeL (`calima-msa-r13`) | 40.5 МБ, GPL-2 | **пользователь**, конвертером | ~40 МБ |
| модель ArabGlossBERT int8 | CC BY-SA 4.0 | скачивается в приложении по желанию | ~135 МБ |

Приложение **не содержит словарных данных в APK**. Первый запуск — мастер импорта:
пользователь кладёт файлы паков в папку и импортирует. Без паков приложение показывает
пустой экран с инструкцией.

### 5.2 Формат пака

Единый контейнер: `SQLite` + таблица метаданных (`schema_version`, `source`, `license`,
`build_date`, `entry_count`, `language_from`, `language_to`) + FTS5-индекс для поиска
по определению. Требования к схеме — в `docs/architecture.md`, §4.

## 6. Качество

### 6.1 Метрика

Основная метрика продукта — **«нужное значение есть в попапе»**: пользователь читает
и выбирает сам. Считается на фикстуре из 200 слов (набор собран из частотного списка,
размечен вручную).

Дополнительная метрика — «первый смысл верен» (для автозаполнения карточки без чтения).

### 6.2 Целевые значения

| метрика | цель | измерено |
|---|---|---|
| нужное значение в попапе (3 статьи) | ≥ 90% | **93.0%** |
| то же, без ответов «имя собственное» | ≥ 85% | 89.0% |
| первый смысл верен (с моделью и порогом) | ≥ 75% | 76.6% (оценка) |
| ложных срабатываний класса «имя собственное» | 0 | 0 |

Регрессия недопустима: ответ базового пайплайна обязан оставаться первой статьёй попапа,
новые кандидаты только добавляются ниже.

### 6.3 Порядок в попапе

1. Ответ базового пайплайна (словарное голосование) — всегда первым.
2. Статьи по леммам, до трёх всего.
3. Если модель уверена в другом смысле — этот смысл поднимается внутри своей статьи,
   сама статья остаётся на своём месте.

### 6.4 Порог модели

Модель меняет порядок смыслов только если разрыв вероятности «лучший смысл минус текущий»
≥ 0.3. Без порога она портит верные ответы в 32% случаев и метрика падает ниже базовой.

### 6.5 Производительность

| операция | цель |
|---|---|
| поиск по пакам (p95) | < 150 мс |
| полный попап без модели (p95) | < 250 мс |
| полный попап с моделью (p95) | < 700 мс |
| холодный старт до готового попапа | < 2 с |
| память в фоне | < 80 МБ |

## 7. Лицензии и правовые ограничения

- Приложение **open source**, лицензия **GPL-3.0** (из-за GPL-2 морфологической базы CAMeL
  и GPL-3 анализаторов; для открытого проекта это осознанное решение, а не препятствие).
- Словарные данные не распространяются с приложением: KSAA запрещает перепубликацию,
  Hans Wehr охраняется авторским правом. Пользователь готовит паки сам для себя.
- Kaikki и модель ArabGlossBERT — CC BY-SA 4.0: указание авторства обязательно,
  производные под той же лицензией. Атрибуция — в README и на экране «О программе».
- Название приложения и репозитория **не должно** содержать «Hans Wehr» и «KSAA».
  Атрибуция — только в README и на экране «О программе».
- В репозиторий не попадают: `*.sqlite`, `*.jsonl*`, `*.xml`, `*.csv`, `*.tsv`,
  каталог `data/`, модели. Это уже настроено в `.gitignore`.

## 8. Приватность

- Ничего не отправляется в сеть, кроме опциональной загрузки модели (по кнопке).
- Чтение экрана (`AccessibilityService`) используется только для получения предложения
  вокруг выделения; текст не сохраняется и не передаётся. Явное уведомление при включении.
- История запросов — локальная, отключаемая, чистится одной кнопкой.
