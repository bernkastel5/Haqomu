# Арабский словарь из меню выделения + Anki — оценка реализуемости

Дата: 2026-11-13. Статус: только исследование, кода нет.

---

## 1. Итог в двух строках

**Android — да, ровно как задумано, MVP за 1–2 недели неполного дня.**
**iOS — нет, «иконки рядом с „Копировать“» там не существует в принципе**, максимум Share/Action extension в 3 тапа.

Главный риск не в UI и не в Anki, а в двух местах: (1) словарь отдаёт данные через **неофициальный** эндпоинт, (2) **ранжирование результатов шумное** — на этом съедается больше всего времени.

---

## 2. Платформа: как вообще попасть в меню выделения

### Android — `ACTION_PROCESS_TEXT` (API 23+)

Это официальный механизм, тот же, через который в меню попадают «Перевести», Wikipedia и т.п.

```xml
<activity
    android:name=".LookupActivity"
    android:label="معجم"                       <!-- только текст, иконку нельзя -->
    android:exported="true"                    <!-- иначе SecurityException -->
    android:theme="@style/Theme.Translucent.NoTitleBar"
    android:launchMode="singleTop"
    android:excludeFromRecents="true">
    <intent-filter>
        <action android:name="android.intent.action.PROCESS_TEXT" />
        <category android:name="android.intent.category.DEFAULT" />
        <data android:mimeType="text/plain" />
    </intent-filter>
</activity>
```

```kotlin
val word = intent.getCharSequenceExtra(Intent.EXTRA_PROCESS_TEXT)?.toString()
val readonly = intent.getBooleanExtra(Intent.EXTRA_PROCESS_TEXT_READONLY, false)
```

Ограничения, которые надо принять заранее:

| Ограничение | Следствие |
|---|---|
| Пункт обычно уезжает в overflow (⋮) | Реальный путь: выделил → ⋮ → «معجم». Не «рядом с копировать» и не по свайпу. |
| Иконку задать нельзя, только `android:label` | В меню будет текст. Короткий, арабский + латиница? Лучше один короткий вариант. |
| Хост-приложение должно объявить `<queries>` (Android 11+) | В части приложений тебя **не покажут вообще**. Известный баг-паттерн: приложение не декларирует PROCESS_TEXT → меню пустое. Chrome/Firefox ок, кастомные — нет. |
| Не работает там, где текст рисуется сам | Flutter `SelectableText`, игры, Unity, многие PDF-вьюеры, часть WebView-приложений, кастомные ридеры. Для изучающих язык это больно: именно ридеры часто «не умеют». |
| Нет позиции тапа | Придёт выделенный фрагмент: может быть слово, фраза, абзац. Решать, что искать, — задача приложения. |
| Холодный старт | Диалог должен открыться < 300 мс → лёгкая Activity, без тяжёлой инициализации; сеть уже потом, со скелетоном. |

Обходы для «неподдерживающих» приложений (если понадобится): AccessibilityService с плавающей кнопкой / чтением выделения — но это отдельная история с рисками модерации в Play.

### iOS — механизма нет

Сторонним приложениям запрещено встраиваться в меню выделения / Look Up. Реальные варианты:

1. **Share / Action extension** — «выделил → Поделиться → приложение». Самый честный путь, 2–3 тапа, стандартный UI-паттерн.
2. **Кастомная клавиатура** — работает везде, включая поля ввода, но требует «Full Access» и ломает привычный ввод.
3. **Shortcuts** — выделил → Поделиться → шорткат.
4. **Своя читалка/браузер** — только для чтения внутри приложения, зато идеальный UX (как Yomitan).

Вывод: iOS-версия — это **другой продукт**, а не порт. Кросс-платформенный фреймворк тут не спасает: экономит UI, но не решает платформенную дыру.

## 3. Словарь KSAA: что удалось выяснить

### Официального API нет

- `https://dictionary.ksaa.gov.sa/developers` — заглушка, в отрендеренном JS-чанке буквально `"developers works!"`.
- В условиях использования прямо: «لا يتطلب معجم الرياض إنشاء حسابات مستخدمين، ولا يوفّر خدمات تأليف أو إسهام أو **شاشات مخصّصة للمطوّرين**» — то есть ключей/кабинета разработчика не предусмотрено.
- Сайт — Angular SPA; бандл `chunk-67XDB735.js` содержит конфиг: `baseUrl: "https://siwar.ksaa.gov.sa/api"`.

### Рабочий эндпоинт (проверено вручную, 2026-11-13)

```
GET https://siwar.ksaa.gov.sa/api/riyadh/Result/SearchEntriesWeb?word=<слово>
```

- Без ключа, без авторизации, `200`, `application/json`.
- Ответ — массив входов; по слову «كتاب» ≈ 34 КБ, бывает до 160 КБ.
- Время ответа из Европы: **0.9–2.0 с** (не идеально для «мгновенного попапа» → нужен кэш + prefetch).
- Нет результата → `200` и `[]` (не 404).
- 12 параллельных запросов — все 200, троттлинга не заметил (но это не значит, что его нет).
- **CORS закрыт**: `Access-Control-Allow-Origin` отдаётся только для `dictionary.ksaa.gov.sa`. Веб/PWA напрямую не смогут; нативному приложению всё равно.

Поля ответа (на каждый вход): `entry` (с огласовкой), `unDiacWord`, `mainPOS`, `subPOS`, а внутри `resultSenseDTO`: `definition`, `englishTranslation`, `example` (в т.ч. коранические), `root`, `pattern` (وزن), `synonyms`, `opposites`, `derivatives`, `conjugation`, `brokenPlural`, `gender`, `isQuranExist`, `wikipediaLink`, `theme`, `usageLevel`… То есть данных **больше**, чем нужно для карточки.

Соседние эндпоинты того же API: `/riyadh/Result/SameRoot?root=...`, `/riyadh/Search/GetLetterWords?id=...`, `/riyadh/Result/DayWord`, `/year-word/current`.

### Правовая часть (из /terms)

- «يتيح معجم الرياض محتواه للبحث، والتصفح، والاستفادة العلمية والثقافية» — поиск и научное использование разрешены.
- «عند استخدام محتوى المعجم في ... التطبيقات، يجب الإشارة بوضوح إلى: معجم الرياض للغة العربية المعاصرة، مجمع الملك سلمان العالمي للغة العربية» — **атрибуция обязательна** при использовании в приложениях.
- «لا يجوز نسخ محتوى المعجم كاملًا أو إعادة نشره على نحو ينافس المعجم» — то есть **никакого зеркалирования дампа**, только on-demand запросы + умеренный кэш.

Практический вывод: личный инструмент — ок; публикация в сторах — лучше сначала письмо в KSAA (они охотно дают разрешения на языковые проекты), а в приложении — видимая атрибуция и ссылка на источник. Не называть приложение «KSAA»/«معجم الرياض» — только упоминание внутри как источника.

## 4. Морфология и ранжирование — главная недооценённая работа

Хорошая новость: бэкенд сам нормализует часть форм.

| Запрос | Что вернул первым | Оценка |
|---|---|---|
| وبالكتاب | كِتَاب | ок, клитики срезаны |
| مدرسين / مدرسون | مُدَرِّس | ок |
| مستشفيات | مُسْتَشْفًى | ок |
| الذهاب | ذَهَاب | ок |
| سيارات | سَيَّارَة | ок |

Плохая новость: **порядок результатов нельзя брать как есть**.

| Запрос | Топ-результат | Что нужно было |
|---|---|---|
| كتب | كُتِبَ (пассив) | كِتَاب / كَتَبَ |
| البيوت | «اَلْبُيُوت اَلْمَحْمِيَّة» (составной вход) | بَيْت |
| ذهب | ذُهِبَ | ذَهَبَ / الذَّهَب |
| أطفال | «أَطْفَال اَلْأَنَابِيبِ» | طِفْل |
| مسلمون | **0 результатов** | مُسْلِم |

Отсюда обязательный клиентский слой:

1. **Нормализация**: снять огласовки/татвиль, унифицировать `أ إ آ ا`, `ى/ي`, `ة/ه`, `ؤ/و`, `ئ/ي`, кашиду.
2. **Отсечение клитик**: `و ف ب ك ل ال` впереди, `ها هم هن كم ك نا ين ون ات ة ي ه` в конце — с генерацией нескольких кандидатов, а не одного.
3. **Ранжирование**: точное совпадение `unDiacWord` с нормализованной формой — максимальный вес; штраф за многословные входы (составные термины); бонус за совпадение POS; бонус за корень, если совпал.
4. **Кэш** «запрос → выбранный entryId», чтобы второй раз открывалось то же значение.
5. **Мягкая деградация**: `[]` (например, «مسلمون») → откат на `SameRoot` и на усечённые кандидаты; для диалектов (египетский/левантийский в соцсетях) «нет в словаре» будет часто — это нормально, нужно красивое пустое состояние.

Оценка: правила деинфлексии + ранжирование — 10–15 часов работы и потом бесконечная полировка. Если хочется обновлять правила без релизов, это аргумент за тонкий прокси.

## 5. Anki

**Android** — `AnkiDroid` Instant-add API (ContentProvider, LGPL):
```kotlin
if (AddContentApi.getAnkiDroidPackageName(ctx) != null) {
    val api = AddContentApi(ctx)
    api.addNote(noteTypeId, deckId, arrayOf(word, definition, example, root, translation), tags)
}
```
Плюсы: карточка кладётся без диалога, можно завести собственный note type (Слово/Значение/Пример/Корень/Вес/Перевод/Аудио). Нужно: проверка «AnkiDroid не установлен» → фолбэк на `ACTION_SEND`, обработка дубликатов, разово — выбор колоды/модели, «Undo» после добавления.

**iOS** — только URL-схема (AnkiMobile ≥2.0.30, приложение платное ~$25):
```
anki://x-callback-url/addnote?profile=User%201&type=Basic&deck=Arabic&fldFront=...&fldBack=...&tags=...&x-success=...
```
Ограничения: поля как HTML, URL надо экранировать, длина URL, локальные медиа не поддержаны (только ссылки на файлы по URL). Рабочий вариант, но хрупкий по сравнению с Android.

Не рекомендую: self-hosted AnkiConnect (только desktop), прямой логин в AnkiWeb.

## 6. Предлагаемая архитектура

**Клиент** — Kotlin + Compose, один модуль:
- `LookupActivity` (PROCESS_TEXT, translucent) → Compose-диалог со значением, примерами, корнем, кнопками «+ Anki», «Открыть на сайте», TTS.
- `Deinflector` (чистые Kotlin-правила) + `Ranker` + `Cache` (Room/DataStore).
- Сеть: OkHttp + kotlinx.serialization; парсить только нужные поля (ответ режем в маппере).

**Тонкий прокси** (Cloudflare Worker / маленький сервис) — очень советую, даже для нативной версии:
- обрезка 34–160 КБ → 2–5 КБ (скорость на мобильной сети);
- серверная нормализация/ранжирование → правки без релиза;
- кэш и rate-limit, «рубильник» при поломке апстрима;
- подмена на резервный источник (Wiktionary/arramooz/ejtaal) при отказе;
- заодно решает CORS, если когда-нибудь появится веб-версия;
- убирает из логов апстрима IP пользователей (приватность).

**Резервный источник** держать с первого дня, хотя бы как «нет сети/апстрим лёг → покажем минимум». Офлайн-словарь в файлах — как **опциональная** загрузка для тех, кто хочет (ваше «без файлов словарей» остаётся дефолтом).

## 7. Оценка трудозатрат

| Блок | Android |
|---|---|
| Каркас + PROCESS_TEXT + translucent Activity | 3–4 ч |
| Сеть, модели, маппинг ответа | 4–6 ч |
| UI диалога (RTL, кегль, примеры, табы по значениям) | 6–8 ч |
| Деинфлексия + ранжирование | 10–15 ч |
| Кэш + история | 3–4 ч |
| AnkiDroid интеграция + настройки колоды/модели | 4–6 ч |
| Атрибуция, политика приватности, иконка, экраны стора | 3–5 ч |
| Тесты на 3–4 устройствах в разных приложениях | 4–6 ч |
| **MVP** | **~35–55 ч** (1.5–2 недели неполного дня / 5–7 полных дней) |
| iOS-версия (Share extension + Anki URL + $99/год) | +20–30 ч |
| «Продукт для людей»: полировка, баги, поддержка | 4–8 недель календарно |

## 8. Чеклист подводных камней

1. Иконки рядом с «Копировать» не будет — только текстовая подпись, часто в overflow.
2. В части приложений пункт не появится вообще (`<queries>` у хоста, кастомный рендер текста).
3. iOS — другого механизма нет, это отдельный продукт.
4. Выделение ≠ слово: придёт фраза/абзац, нужен свой парсер.
5. Огласовки, татвиль, варианты `أ/ا`, `ة/ه`, клитики — без деинфлексии попадания будут случайными.
6. Ранжирование апстрима шумное: составные входы лезут в топ, пассивные глаголы вместо базовой формы.
7. Пропуски в покрытии (пример: «مسلمون» → 0) и диалекты → нужен fallback и хорошее пустое состояние.
8. Нет офлайна: 1–2 с и обязательная сеть; без кэша ощущается как «тормознутое».
9. Неофициальный эндпоинт → может измениться/закрыться; нет SLA, нет ключей; нужен прокси + второй источник.
10. CORS закрыт → любая веб-версия только через свой прокси.
11. Юридически: атрибуция обязательна, зеркалировать дамп нельзя, разрешение на стор лучше спросить заранее, имя «KSAA» не использовать как бренд.
12. Приватность: выделенный текст уходит третьей стороне — надо явно сказать в политике; прокси без логов помогает.
13. Anki-модель карточки: спроектировать поля один раз и хорошо, миграция потом болезненна.
14. Холодный старт диалога: тяжёлая инициализация убьёт весь смысл «быстрого попапа».
15. Соблазн фич (озвучка, синонимы, корень, коранические примеры, весь `derivatives`) — легко утонуть; в MVP выбрать 4 поля.
16. Play: target API level обновляется каждый год, политика приватности обязательна, ревью низкорисковое.

## 9. Что бы я сделал следующим шагом

1. **Прототип на полдня**: процесс-текст активити + запрос к эндпоинту + сырой вывод JSON. Проверить на живом телефоне в Chrome, Twitter/X, Kindle, PDF-ридере — сразу видно, где пункт не появляется.
2. **Тест ранжирования**: прогнать 100–200 реальных слов из своих текстов, посмотреть долю «топ-результат верный». Это главная метрика проекта; если она < 60 % — без своего ранкера/прокси делать нечего.
3. **Письмо в KSAA** (арабский, 1 абзац): «делаю бесплатный инструмент для изучающих, хочу использовать SearchEntriesWeb, с атрибуцией» — либо разрешат, либо дадут официальный путь.
4. Решить про iOS: делать сразу (плюс 3 недели, другой UX) или Android-only и потом расширяться.
