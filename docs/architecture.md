# Архитектура пайплайна: итоговая версия

Все цифры получены на наборе из 200 арабских слов (частотный список, ручная разметка)
и на 101 живом предложении (Tatoeba + арабская Википедия, ручная разметка). Ссылки на
исходные скрипты — для портирования, не для поставки.

---

## 1. Общая схема

```
выделение текста (любое приложение)
        │  слово + опционально предложение
        ▼
[1] Нормализация            harakat, tatweel, ا/أ/إ/آ, ى/ي, ة/ه
        ▼
[2] Класс слова             словарное / форма с клитикой / имя собственное
        │                   нет разбора CAMeL + нет основы в словаре → «имя»
        ▼
[3] Леммы                   до 2 лемм CAMeL (calima-msa-r13)
        ▼
[4] Кандидаты из словарей   KSAA (арабо-арабский) · Hans Wehr · Kaikki · Коран
        ▼
[5] Выбор внутри словаря    подтверждение кандидата другими словарями
        ▼
[6] Голосование между       ksaa → kaikki → wehr
    словарями
        ▼
[7] Порядок смыслов         ArabGlossBERT, только если есть предложение
    (опционально)           и разрыв вероятности ≥ 0.3
        ▼
[8] Сборка попапа           до 3 статей, все смыслы каждой
        ▼
   карточка в Anki
```

## 2. Стадии

### 2.1 Нормализация

Снимаем огласовку и татвиль, унифицируем алеф (ا/أ/إ/آ), ى/ي, ة/ه. Оригинал храним
для показа и для карточки. Та же нормализация, что в `tools/name_class.py::key()`.

### 2.2 Класс слова

**Задача:** не выдать значение случайного арабского слова там, где словарной статьи нет.

Правила (порядок важен):

1. CAMeL `calima-msa-r13` дал разбор → обычное слово.
2. Разбора нет → раскладываем на клитику и основу (префиксы `وال بال كال فال لل ال ها أ و ف ب ك ل`,
   суффиксы `هما كما هم هن ها نا ني ون ين ات وا ه ك ت ي`). Требуется одновременно:
   - основа есть в словаре (KSAA возвращает статью с такой головой);
   - CAMeL разбирает саму основу;
   - аффикс совместим с частью речи: глагольное окончание — только при основе-глаголе
     и показателе `ا/أ` в начале; притяжательное — при имени, прилагательном или глаголе;
     слабую букву восстанавливаем только при притяжательных окончаниях;
   - служебным основам (`هو`, `هذا`) словарная статья не требуется.
3. Ничего не подошло → «похоже на имя собственное».

**Измерено:** 8 из 12 транслит-имён в наборе поймано, ложных срабатываний 0.
Не пойманы `آندي`, `تومي`, `ماتي`, `كوتون` — CAMeL разбирает их как арабские слова.
Реализация: `tools/name_class.py`.

### 2.3 Леммы

CAMeL выдаёт лемму в поле `lex`, сортируем по `lex_logprob`, берём две старшие.
**Измерено:** верная лемма попадает в список в 13 из 14 содержательных промахов.
Анализатор AlKhalil на инфинитивных формах ошибается чаще (`فرانك` → `وفر`, `عليك` → `عل`),
поэтому он в итоговой версии не используется.

### 2.4 Кандидаты из словарей

| источник | что даёт | роль |
|---|---|---|
| KSAA (арабо-арабский) | определение на арабском, примеры, английский эквивалент | основной ответ |
| Hans Wehr | английские значения, корень, породы | подтверждение и перевод |
| Kaikki (Wiktionary) | английские глоссы, порядок смыслов ≈ употребительность | подтверждение и запасной ответ |
| Коран | вхождения, огласовка, контекст | справка |

Запрос к KSAA делается и по словоформе, и по каждой из лемм; статьи объединяются,
дубли снимаются по паре «голова + первый смысл» (иначе теряются статьи с той же головой,
но другим смыслом — например `رائحة` «запах»).

### 2.5–2.6 Выбор и голосование

Правило: кандидаты от всех источников → внутри словаря побеждает тот, который подтверждён
снаружи → между словарями приоритет `ksaa → kaikki → wehr`. Плюс фильтр: однословные
заголовки, без коранических помет, без пассива, без имён собственных, если есть альтернатива.
Реализация: `tools/pipeline_full.py`.

**Измерено (на 200 словах):**

| конфигурация | верно | верно + част. |
|---|---|---|
| только KSAA с ранжированием | 108 (57%) | — |
| кросс-словарное подтверждение | 128 (68%) | — |
| полный пайплайн | **133 (71%)** | **84%** |
| без анализатора | 129 | — |
| без фильтра | 131 | — |

### 2.7 Порядок смыслов (опционально)

Cross-encoder `SinaLab/ArabGlossBERT` (AraBERT-base, 135.2 млн параметров, CC BY-SA 4.0),
задача — «подходит ли это толкование этому предложению», на выходе вероятность.

**Правило:** смысл меняется только при разрыве вероятностей ≥ 0.3. Иначе — словарный порядок.

**Измерено:** 76% на парах «предложение + толкование» (случайность 50%), 68% на 101 живом
предложении без порога; с порогом 0.3 модель молчит в 82% запросов, не ломает верное в 96%
и исправляет треть неверного, что даёт ~76.6% против 70% у словарного порядка.
Квантование в int8 точность не меняет (69/101 в обоих случаях).
Реализация: `tools/eval_live.py`, `tools/eval_int8.py`, `tools/pipeline_v2.py`.

### 2.8 Сборка попапа

До трёх статей: ответ пайплайна всегда первым, дальше статьи по леммам.
Все смыслы статьи видны. Английские эквиваленты — под арабским определением.

**Измерено:** нужное значение в попапе — 93.0% при трёх статьях, 91.0% при двух,
88.0% при одной; без ответов «имя собственное» — 89.0 / 87.0 / 84.0%.

### 2.9 Путь цифр

| шаг | метрика «значение в попапе» |
|---|---|
| KSAA с ранжированием | 57% |
| + кросс-словарное голосование | 68% |
| + анализатор и фильтр | 71% (84% с учётом «верная статья, не тот смысл») |
| + класс имени, леммы CAMeL, три статьи | **93%** |

## 3. Что проверено и отклонено

| подход | результат | почему отклонено |
|---|---|---|
| приор порядка смыслов по словарным сигналам | +3 слова ценой 51 переписанного ответа, 7 регрессий | плохая сделка |
| генеративная модель 0.6B на устройстве | 0/10 при балансировке порядка, ответ «первый вариант» в 100% | нет способности |
| отрезание клитик без проверки части речи | `جاكي` → `جاك`, `كوتون` → `كوتون` как слова | ложные срабатывания, правило переписано |
| модель без порога уверенности | портит 32% верных ответов | хуже словарного порядка |

## 4. Формат пака

Один файл SQLite на пак:

```sql
CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT);
-- schema_version, source, license, build_date, entry_count, lang_from, lang_to

CREATE TABLE entry (
  id INTEGER PRIMARY KEY,
  head TEXT NOT NULL,          -- огласованная голова
  head_norm TEXT NOT NULL,     -- нормализованная (без хараката, унифицированные буквы)
  root TEXT,
  pos TEXT,
  pattern TEXT,
  source TEXT
);
CREATE INDEX idx_entry_norm ON entry(head_norm);
CREATE INDEX idx_entry_root ON entry(root);

CREATE TABLE sense (
  id INTEGER PRIMARY KEY,
  entry_id INTEGER NOT NULL REFERENCES entry(id),
  ord INTEGER NOT NULL,        -- порядок внутри статьи
  definition TEXT NOT NULL,    -- арабское определение или английский глосс
  gloss_en TEXT,
  example TEXT,
  tags TEXT                    -- مجاز / كناية / قرآني / مطاوع
);
CREATE INDEX idx_sense_entry ON sense(entry_id);

CREATE VIRTUAL TABLE sense_fts USING fts5(definition, gloss_en, content='sense', content_rowid='id');
```

Конвертер морфологической базы CAMeL делает из текстового `morphology.db` компактный
бинарный файл с таблицей «словоформа → разбор» и индексом по префиксу.

## 5. Что портировать в первую очередь

1. `tools/name_class.py` — правила класса слова. Чистая логика плюс два обращения
   к морфологической базе и к словарю.
2. `tools/pipeline_full.py` — сбор кандидатов, поддержка внутри словаря, голосование.
3. `tools/pipeline_v2.py` — сборка попапа из трёх статей (обвязка над первыми двумя).
4. `tools/build_hw_pack.py` — схема пака Hans Wehr; эталон того, как выглядит готовый пак.
5. `tools/build_kaikki_index.py` — формат индекса Kaikki.
6. `tools/eval_live.py` — как устроен замер; нужен для регрессионного прогона после порта.

## 6. Известные ограничения

- Остаток промахов на 200 словах (12): `المرأة` — статьи «женщина» в KSAA нет;
  `المنزل` — «дом» шестым из восьми в ответе KSAA; `عرفت`, `عليك`, `لأحد`, `تراه`,
  `سأتابع` — порядок статей и дыры покрытия самого словаря; имена `آندي`, `تومي`, `ماتي`,
  `كوتون`.
- Контекст предложения доступен не во всех приложениях: `AccessibilityService` видит
  только то, что приложение отдаёт в дерево доступности.
- Набор из 200 слов собран из субтитров: в нём 12 транслит-имён. В новостях и книгах
  их доля другая, метрика сместится.
- Порог 0.3 выбран на том же наборе, на котором измерен: на отложенных данных ждать
  немного ниже.
